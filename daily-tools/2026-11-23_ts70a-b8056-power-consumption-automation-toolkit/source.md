TS70A-B8056_PC_test.sh（v1.18）是一支 2298 行的互動式選單 Bash 工具，把「伺服器功耗移交測試」SOP 整段自動化：兩台機器（SUT + Client）透過 Intel E810 網卡對接，同時對 CPU、記憶體、網卡、硬碟四項下壓力（stress-ng + fio + ib_write_bw/iperf），每秒記 CPU/記憶體用率、每 15 秒用 ipmitool 記 DCMI/PSU 功耗與溫度，測完自動判定 PASS/FAIL，結束後還會把網路設定還原成測試前的原始狀態並自動比對驗證。

## 為什麼值得關注

功耗移交測試（Power Consumption handover test）是伺服器送進溫箱前的必經關卡：要把機器組成「最耗電配置」，CPU/記憶體/網卡/硬碟同時全力運轉 15 分鐘以上，同時記錄功耗與溫度曲線給 RAD 判斷能不能進溫箱。這件事如果靠人工，光是「兩台機器的網卡要怎麼對接」「測完要不要記得把 IP 設定還原」「風扇到底有沒有真的被設成 100%」這類細節就很容易出錯——而這份素材最值得看的地方，是 README 裡誠實留下的六次整合測試實測記錄：第一次重開機後發現 8 顆硬碟沒被偵測到，但舊版本（v1.17）仍然判定 PASS；風扇選單選了「100%」，BMC 卻其實還在自動控制，數據因此不能用。這些都是真實測試中踩到的坑，逼著工具從 v1.0 一路加防呆版到 v1.18，等於是一份「自動化測試工具怎麼從被資料騙到學會自我驗證」的活教材。

## 技術重點

實際下載 `03_Tools/TS70A-B8056_PC_test.sh`（2298 行）與 `01_Document` 底下的 SOP 文件、`04_Log` 的實測 log 後，幾個做得紮實的地方：

- **組態基線防呆（v1.18 的核心改版）**：第一次讀取組態（CPU 型號/數量、記憶體、E810 埠數與 PCIe 寬度、SUT 另外列 NVMe 控制器與 PCI 位址）時要操作者按 1 確認，存進工具資料夾外的 `/var/lib/pc_test/config_baseline.state`；之後每次要開始測試前（選硬碟、寫入之前）自動比對一次，少了什麼就列出 `[MISS]`、多了什麼列 `[DIFF]`，直接 `[STOP]` 擋下測試，不像舊版那樣硬碟少了 8 顆還照樣跑完給 PASS。
- **網卡自動配對與子網段分配**：選單 `a` 列出本機所有 `ice` driver 的 E810 埠，讓操作者輸入「有接線的埠」與「對方對應的埠」（支援 `0-3,8,10-12` 這種範圍語法），自動產生 `nic_pairs.conf`，每組配對各配一個 `192.168.10x.x` 子網段，兩組撞到同網段時選單會直接拒絕；檔案裡的 `auto:N` 代表「執行腳本那台機器上第 N 個 E810 埠」，所以同一份設定檔兩台機器都能直接共用。
- **網路狀態可還原並自動驗證**：第一次改動網卡設定前，`sysread`/`ns_*` 一類的函式會先把 MTU、連線狀態、IP、DHCP 與否、IPv6 link-local、防火牆狀態存成原始快照；全部測完選 `r`，工具列出目前與原始的差異，還原後再比對一次，全部一致才顯示 `[ OK ]`，否則列出 `[FAIL]` 與差異明細——角色與配對資訊也刻意存在工具資料夾外（`/var/lib/pc_test/role`），避免重新上傳資料夾把設定蓋掉。
- **FIO 自動試驗找最佳參數**：選單 `s → 5` 會依序自動試「目前設定 → shared 排程 → shared + 關閉時間戳記 → 加 CPU」等組合，每組跑 60~120 秒比較達標硬碟數與總寫入量，README 裡附的實測數據是從 19/27 顆達標、總寫入 130.9 GiB/s，調到 27/27 顆達標、166.8 GiB/s——調整的是 `iodepth`、批次大小（`iodepth_batch_submit`）、CPU 分配方式（`split` vs `shared`），不是靠加更多 CPU 核心換效能。
- **功耗與溫度採樣務實**：`Power/` 底下用本機 `ipmitool` 每 15 秒讀一次 DCMI、PSU 輸入/輸出功耗、各感測器溫度與風扇轉速，並額外存一份 `sensor_thresholds.list` 記錄每顆感測器的警告/嚴重上下限，方便直接看「離上限還差幾度」；README 明講這只是參考值，正式報告仍要靠 MiCoreView，工具沒有想取代既有量測系統。

## 可延伸應用角度

- 可以搭配先前已收錄的硬體壓力測試系列（PTU_CPU_Verify、MaxHDD Patrol、C-State Idle Power Logger）做成一集「SIT 實驗室的功耗/溫度量測工具怎麼寫」的比較，重點放在「怎麼用 ipmitool 和 /proc 介面量測，不依賴額外 SDK」。
- README 裡六次整合測試的除錯歷程（硬碟漏偵測、風扇設定不實、網卡連線逾時）本身就是很好的「真實測試案例復盤」素材，適合做成一支「自動化測試工具的版本是怎麼被 bug 逼出來的」短片，對照 v1.0 到 v1.18 的變更紀錄逐條講。
- 組態基線比對（confirm once, diff every run）這個防呆模式可以抽出來做成通用教材，示範怎麼用一個「存一次、每次跑前都比對」的輕量機制擋掉「環境悄悄變了但測試還是給過」這類資料不可靠的問題。
