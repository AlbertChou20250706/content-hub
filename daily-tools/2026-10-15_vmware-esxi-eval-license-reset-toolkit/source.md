`update_esxi_license.sh` 把「重置 VMware ESXi 60 天評估授權」這個原本靠 PuTTY 手動打三行指令的流程，改寫成一支帶防呆、帶 log 的腳本。ESXi 評估期到期後，手動流程是連進主機、把 `license.cfg` 改名備份、用原廠留存的 `.#license.cfg` 蓋回去、重啟 `vpxa`——三個步驟，中間任何一步打錯就可能讓主機沒有 license 檔或蓋掉正式授權。

## 為什麼值得關注

SIT 測試機常年跑在評估模式下（測試用途不需要正式授權），60 天一到就要手動跑一次這組指令，次數一多難免出錯：原始手動筆記（`Input command to the info.jpg`）裡第一行的目的路徑其實寫漏了開頭的 `/`，照抄會把檔案放錯位置。這種「連範本筆記本身都有 bug」的情況，正是把流程腳本化、而不是繼續靠人手抄的理由。腳本的核心價值不是省那三行指令的打字時間，而是把「先確認、失敗要還原」這套安全邏輯寫死，不靠人記得小心。

## 技術重點

讀過 README 和腳本原始碼後，幾個值得注意的設計：

- **動手前先驗證模式**：腳本用 `vim-cmd vimsvc/license --show` 確認主機真的處於 Evaluation Mode，如果已經裝了正式授權就直接中止，除非明確加 `--force`——避免把客戶或正式環境的授權誤蓋掉。
- **`cp` 失敗自動還原**：`mv` 完舊檔之後若 `cp` 原廠檔失敗，腳本會把剛剛搬走的 `license.cfg` 放回去，不會讓主機落在「沒有任何 license 檔」的中間狀態。
- **備份不覆蓋**：如果 `license.cfg.old` 已經存在（代表不是第一次重置），會先改名成帶時間戳的版本再繼續，舊備份不會被無聲蓋掉。
- **密碼不落地**：互動模式密碼由 `ssh` 自己詢問，非互動（排程／agy 代跑）模式透過環境變數 `ESXI_PASSWORD` 搭配臨時 `SSH_ASKPASS` 小程式傳給 `ssh`，用完即刪，密碼本身不寫進任何檔案或 log；log 與畫面上授權金鑰一律遮成 `*****`。
- **`--dry-run` 與結束碼分層**：提供只檢查不動手的模式，且用 0/1/2/3/4 五種結束碼分別對應「完成／參數錯誤／連線失敗／安全檢查中止／重置失敗」，方便排程腳本依結束碼分流處理，而不是只看成功或失敗兩種結果。
- **誠實記錄交接邊界**：README 明確寫「交給 agy 之前先看 `AGENTS.md`」，並規定 agy 必須先 `--dry-run`、正式重置要等人明確確認、不得用 `--force`、關 SSH 與斷 AC 只能由人親自做——把「哪些步驟人類不能委派」寫清楚，而不是假設自動化可以一路做到底。

## 可延伸應用角度

- 適合跟之前收錄的 SIT 自動化工具（`StartRAIDCC`、`WithMaxHDDFunctionTest` 等）放進同一個「自動化腳本安全網設計」系列，這支工具補的是「驗證模式、失敗自動還原、密碼不落地」這幾個新角度。
- `AGENTS.md` 裡「哪些步驟交給 agy、哪些步驟必須留給人」的分界，可以單獨剪一段做「怎麼幫自動化腳本寫清楚人機分工守門規則」的示範素材。
- 原始手動筆記裡那個漏掉 `/` 的路徑錯誤，是很好的「為什麼不能照抄截圖裡的指令、要腳本化並加驗證」的具體案例片段。
