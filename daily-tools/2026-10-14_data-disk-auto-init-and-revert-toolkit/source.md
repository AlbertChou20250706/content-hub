`make_lvm_disk` 資料夾收著三支 Albert style 的 Bash 腳本，處理 Linux 測試機上最容易出人命的操作——資料碟的初始化與還原：`auto_init_data_disks_v0.2.sh` 自動偵測「安全可初始化」的磁碟，一鍵完成清簽名→GPT→分割→格式化→掛載→寫入 fstab；`revert_data_disk_v0.2.sh` 負責把上述動作安全「倒帶」；`simple_make_partition_v0.1.sh` 則是給單一磁碟手動操作用的簡化版。三支腳本共用同一套「預設 DRY-RUN、白名單強制、系統碟自動保護」的安全哲學。

## 為什麼值得關注

SIT 測試機常常要重複初始化/還原資料碟（掛測試用的資料磁碟、跑完測試再清空還原），這類操作一旦打錯目標裝置就是整台機器報廢的等級。這套工具把「人會犯的錯」直接寫進程式邏輯裡擋掉：沒有明確指定白名單絕不會動手、系統碟（`/`、`/boot`、`/boot/efi` 所在實體碟）會被自動偵測並跳過、預設一律 DRY-RUN，要同時加 `-y` 與 `--include` 才會真的執行。這種「寫死安全網、而不是靠人記得小心」的設計思路，比腳本本身的分割/格式化邏輯更值得拿出來講。

## 技術重點

實際讀過三份 README 後，幾個值得注意的設計：

- **雙保險白名單**：`auto_init_data_disks_v0.2.sh` 即使加了 `-y`，沒有 `--include sdb,sdc…` 一樣不會動手——執行旗標跟目標範圍是兩個獨立的門檻，缺一不可。
- **髒碟保護**：預設跳過「已分割／已掛載／已有檔案系統簽名」的磁碟，除非顯式加 `--force-dirty`；`simple_make_partition_v0.1.sh` 則是要求手動輸入 `YES` 才繼續（`-y` 可跳過，標註為「適合自動化」但危險）。
- **fstab 寫入都帶 `nofail,x-systemd.device-timeout=10`**：三支腳本一致用這組選項寫 `/etc/fstab`，確保測試碟哪天被拔掉或壞了，不會卡住開機——這是從真實故障場景（開機卡在等一顆壞掉的資料碟）回頭補上的細節。
- **`revert_data_disk` 用 UUID 比對刪 fstab**：還原時先抓裝置的 UUID，再拿 UUID（以及可選的掛載點）去比對刪除 `/etc/fstab` 對應行，並自動備份成 `/etc/fstab.bak`，而不是用裝置名稱字串比對（裝置名稱在重開機後可能變動，UUID 才穩定）。
- **已知限制誠實寫在文件裡**：`simple_make_partition_v0.1.sh` 的 README 直接點出 NVMe/mmcblk 類裝置（分割名稱含 `p`，如 `nvme0n1p1`）目前會在建立分割後找不到分割區而中止，且這時磁碟已被清除但尚未格式化——這種「哪裡會壞、壞了會停在哪個半成品狀態」的坦白記錄，比假裝工具完美更有參考價值。

## 可延伸應用角度

- 適合做成「寫自動化腳本時怎麼設計安全網」系列的具體案例：白名單+執行旗標雙保險、系統碟自動偵測、DRY-RUN 預設開啟，這幾個模式可以抽出來套用到任何「會碰硬體/會刪資料」的自動化腳本上，不限於磁碟操作。
- 可以和之前收錄的其他 SIT 自動化工具（如 `StartRAIDCC`、`WithMaxHDDFunctionTest`）串成一個「測試機維運腳本」小系列，對比不同工具在「防呆設計」上的做法異同。
- `simple_make_partition_v0.1.sh` 裡誠實記錄的 NVMe 已知限制，適合剪一段「讀程式碼找邊界case」的片段，示範怎麼從 README 的「已知限制」章節快速抓到工具的安全使用邊界。
