《Digital Brewing Master（數位沖煮大師）》是一個單檔 HTML5 應用程式，把手沖咖啡的配方、基本參數與逐段注水步驟數位化記錄下來，開啟瀏覽器就能用，不需要安裝任何後端伺服器。

## 為什麼值得關注

這份檔案藏在 Albert 個人的「Coffee」資料夾裡，表面上那個資料夾看起來只是沖煮參數截圖與零散的手沖照片，但往下挖一層會找到一個子資料夾 `Scrip/20250331/`，裡面才是真正的應用程式本體：`Website_Coffee_v3.2.html`、一份修正版 `Website_Coffee_v3.2_fix.html`（檔案大小從 27KB 長到 33KB，明顯是中途修了不少東西），以及一份正式的 README。這正好示範了「素材資料夾的真實結構常常比表面看到的深很多」——如果只看第一層的沖煮參數 Excel 跟照片，會完全漏掉底下這個做得相當完整的小工具。

對日常喝手沖咖啡、想把沖煮經驗量化記錄下來的人來說，這個工具提供了一個比「拍照+記在備忘錄」更系統化的做法：固定的參數表格（豆量、水溫、粉水比、悶蒸時間…）加上可編輯的分段注水流程，等於把每一次沖煮都變成一份可以回頭對照、調整的「配方卡」。

## 技術重點

實際打開 `Website_Coffee_v3.2_fix.html` 看過程式碼後，幾個值得注意的設計：

- **完全前端、零依賴後端**：全部邏輯塞在一個 HTML 檔裡（含 HTML 結構、CSS、JavaScript），用 `localStorage` 存檔，雙擊檔案就能在任何現代瀏覽器上跑，不用架 Python/Node 伺服器。
- **資料結構用「配方 → 沖煮法 → 參數/步驟」三層嵌套**：程式碼裡的 `defaultDB.recipes` 陣列預設就內建了「熱Coffee（一般模式）」「冰Coffee（冰模式）」「過濾杯器（V60模式）」「波佐見燒」等好幾種配方，每個配方底下的 `params`（豆量、CC數、粉水比…）與 `steps`（悶蒸、中心小圈、大水繞…逐段注水描述）都是結構化資料，不是純文字，所以才能同時支援表格顯示與匯出。
- **三語切換（中/英/日）**：用 `ml(zh, en, ja)` 這個小工具函式把每個欄位名稱、步驟描述都包成三語物件，`t()` 函式根據目前語言取值回傳，UI 文字跟資料內容都走同一套多語機制。
- **一鍵匯出 ZIP，裡面同時有 CSV / XLSX / JSON 三種格式**：匯出邏輯用 JSZip 打包，Excel 檔是用 SheetJS（`xlsx.full.min.js`，從 cdnjs 載入）即時產生 `.xlsx`，JSON 則是把當前配方、方法與版本資訊整包存成備份檔，三種格式一次到位，不用手動轉檔。
- **深色/高對比/淺色三種主題**，靠 CSS variables 配 `data-theme` 屬性切換，README 裡也明確寫了「如何新增配方」的教學（找 `const APP_DATA` 關鍵字，照 JSON 格式加一塊），對不寫程式的人來說算是相對友善的客製化說明。

## 可延伸應用角度

- 適合做成「這才是真正的工具挖掘」系列開場案例：示範在挖素材資料夾時，不能只看第一層的照片跟 Excel，隨手一個「個人興趣」資料夾底下也可能藏著做得很完整的單檔小工具。
- 可以搭配之前已經介紹過的《README_ToolDB-紀錄CIP》《Excel_design_Sample_for_python_code》等「個人資料記錄系統」系列一起談，比較「用 Excel 記錄」跟「用單檔 HTML App 記錄」兩種做法在資料結構化、匯出彈性上的差異。
- 也適合剪一段「同一個檔案存在兩個版本（v3.2 跟 v3.2_fix）」的對照，聊聊個人小工具在沒有版本控制系統時，怎麼靠檔名手動管理修正版本——以及這跟專案裡其他正式工具動輒用 Git/README Changelog 管理版本的對比。
