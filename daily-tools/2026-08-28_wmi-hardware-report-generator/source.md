## 這是什麼

一支單檔 PowerShell 腳本（`Final_Hardware_Report.ps1`），透過 CIM/WMI 查詢當前機器的 CPU、記憶體、硬碟、網卡、BIOS、CPU 溫度等硬體資訊，產出一份自帶樣式的 HTML 報告，並在報告最上方用一顆圓形進度條顯示 0–100 分的「整體健康分數」。搭配一個 `Run_Final_Report.bat` 雙擊啟動器，不需要另外安裝任何套件，PowerShell 5.1 與 7 都能跑。

## 為什麼值得關注

硬體測試 / IT 資產盤點的日常痛點是：想知道一台機器「現在健不健康」，往往得手動開好幾個工具分別看 BIOS 版本、硬碟 SMART 狀態、網卡協商速度、記憶體用量，再自己判斷有沒有問題。這支腳本把這些檢查點收斂成一個單一分數 + 紅黃綠燈號的報告，對現場工程師或非技術人員來說，雙擊 `.bat`、等幾秒、看報告就好，不用逐項解讀原始數值。這種「一鍵健檢」的形式，跟本週已收錄的 RX4770M8 測試進度管理系統、健康監控工具是同一類實務需求（機台/伺服器狀態要能快速對外交代），但這支更輕量，適合當作教學裡「用最小依賴做出可用報告」的範例。

## 技術重點（實際讀過原始碼）

- 資料來源全部走 `Get-CimInstance`（新一代 CIM cmdlet），涵蓋 `Win32_PnPEntity`（PCI 裝置）、`Win32_PhysicalMemory`、`Win32_Processor`、`Win32_BIOS`、`Win32_NetworkAdapter`、`Win32_DiskDrive`、`Win32_LogicalDisk`、`Win32_OperatingSystem`，沒有用到已淘汰的 `Get-WmiObject`，這是它同時相容 PowerShell 5.1 與 7 的關鍵。
- CPU 溫度用 `MSAcpi_ThermalZoneTemperature`（`root/wmi` 命名空間）讀取，外層包了 `try/catch`：不是所有機器的韌體都會曝露 ACPI 溫度資訊，抓不到就顯示 `N/A` 而不是整支腳本噴錯，這個容錯處理在 8.0.0 版才加上去。
- 健康分數是 5 個面向各佔 20 分、加總封頂 100 分的規則式評分：BIOS 版本是否等於設定值 `$LatestBIOSVersion`、最高網卡協商速度是否 ≥100Gbps、磁碟健康狀態是否為 `OK`、磁碟使用率是否落在安全區間、CPU 負載是否偏高——對照專案裡保留的舊版 `Advanced_Hardware_Report_Interactive.ps1`（v3.2.0）可以看到，舊版只是把每一類資訊套個顏色標籤（pass/info/critical）平鋪列出，沒有任何加總分數；v8.0.0 才把這些標籤收斂成一個可以直接拿來做「go/no-go」判斷的單一數字，這是這支工具從「資訊展示」進化到「健檢報告」的關鍵一步。
- 報告輸出走 `Set-Content -Encoding UTF8` 產生單一 HTML 檔（內嵌 CSS，不需要額外靜態資源），並嘗試呼叫固定路徑下的 `wkhtmltopdf.exe` 轉出 PDF；找不到執行檔時只印黃色警告訊息並跳過，不會讓整支腳本失敗——這種「非核心功能失敗要降級而不是中斷」的寫法值得在教學裡點出來。
- log 檔是用 PowerShell 預設的 `Out-File` 寫入，實際下載下來確認是 UTF-16 LE 編碼（帶 BOM），如果要在教學裡示範用其他語言/工具解析這個 log，這是一個容易被忽略但會讓人卡住的小細節。

## 可延伸應用角度

- 可以跟已收錄的「RX4770M8 測試進度管理系統」「健康監控跨平台工具包」放在同一支影片系列裡，主題定調成「不同規模的硬體健檢工具怎麼做分數化判讀」。
- 直接把 v3.2.0 跟 v8.0.0 的原始碼並排 diff，作為「一支腳本怎麼從『列資料』演化成『給結論』」的迭代式工具設計案例，很適合做成短影片的核心橋段。
- 溫度讀取的 try/catch 容錯、PDF 匯出的優雅降級，都是很小但很適合單獨抽出來講「PowerShell 腳本防呆設計」的片段素材。
