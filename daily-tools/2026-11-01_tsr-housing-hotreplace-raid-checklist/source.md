TSR_Housing 是一份硬碟熱插拔（Hot Replace）測試檢核表，用 Excel 把「RAID 模式」與「Non-RAID 模式」下的抽換測試步驟拆成兩張工作表，逐步列出從建 RAID、跑壓測、熱拔硬碟、看背板 LED、熱插回、等重建完成到比對事件日誌的完整流程。它不是程式碼工具，是 SOP／測試檢核表，這點 README 本身就寫得很直白：「無程式碼，不是可執行的工具」。

## 為什麼值得關注

硬碟熱插拔測試是伺服器驗證裡最怕「看起來過了但其實沒過」的一類測試——抽換當下系統沒當機，不代表 RAID 真的重建成功、LED 燈號真的跟狀態同步、事件日誌裡真的留下正確的 Fail→Rebuild→Normal 轉換紀錄。這份檢核表把「怎麼驗證測試真的做到位」拆成具體步驟，而不是只寫一句「測試熱插拔功能」就交卷。

兩張工作表分別對應機殼可能遇到的兩種上線型態：有建 RAID 的機器要驗證容錯與重建機制本身有沒有正常運作；沒建 RAID、硬碟各自獨立掛載的機器則要驗證系統對裝置增減事件的辨識是否正確、其他 I/O 工作是否不受影響。兩種情境的失敗模式完全不同，分開列檢核表避免驗證時漏看對應的那一半。

## 內容概要

`HotReplace_Test_Checklist.xlsx` 兩張工作表的具體步驟：

- **RAID_Mode**（9 步）：BIOS 開 VMD → 建 RAID1/RAID5 → 開始連續 I/O 壓測（fio、stress-ng）→ 熱拔硬碟（例如 Slot0）→ 確認壓測不中斷 → 確認背板 LED 轉為 Fail 狀態 → 熱插新硬碟 → 確認 LED 轉為 Rebuild 狀態 → 等重建完成且 RAID 恢復 Healthy → 比對三份紀錄（RAID 事件日誌的 Fail→Rebuild→Normal 轉換、壓測日誌、LED 燈號轉換）。
- **NonRAID_Mode**（8 步）：BIOS 開 VMD 但不建 RAID → 確認 OS 能獨立辨識每顆硬碟/SSD（`/dev/sdX`、`/dev/nvmeXn1`）→ 在目標硬碟跑連續 I/O（fio、dd）→ 熱拔硬碟/SSD 並檢查 OS 事件日誌出現裝置移除紀錄 → 確認其他壓測工作不受影響 → 熱插新硬碟/SSD 並檢查事件日誌出現裝置新增紀錄 → 確認新裝置被正確列舉（`lsblk`、`diskmgmt.msc`）→ 重複整組步驟至少 3 次，排除單次成功的僥倖。

每個步驟都有獨立的 Check（打勾框）與 Result/Notes 欄位，是給實際執行測試的工程師填寫、留存紀錄用的表單，不是流程示意圖。

## 可延伸應用角度

- 適合搭配先前介紹過的 RAID/CC 開機驗證類工具，做成「伺服器可靠度驗證的檢核表系列」——重點放在「怎麼把一個模糊的驗收項目拆成可重複執行、可留痕的步驟」，而不是工具操作教學。
- Non-RAID 模式裡「重複 ≥ 3 次」這個要求,是個很好的切角：講清楚為什麼硬體驗證測試不能只跑一次就判定通過,單次成功很可能只是僥倖,多次重複才能排除間歇性故障。
- 也可以作為「如何用 Excel 寫出一份真正有用的測試檢核表」的範例素材——每步驟都對應到具體可觀察的系統狀態（LED 燈號、事件日誌、壓測是否中斷），而不是寫一句空泛的「測試功能是否正常」。
