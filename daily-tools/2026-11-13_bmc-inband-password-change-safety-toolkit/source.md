BMC_Password_Change 是一支在 SUT（待測機）的 Linux 作業系統內，透過本機 IPMI 介面（in-band）用 `ipmitool` 修改 BMC 使用者密碼的互動式 Bash 工具，不需要連 BMC 網頁、也不需要從另一台機器連進 BMC。

## 為什麼值得關注

手動改 BMC 密碼（`ipmitool user set password <使用者ID>`）看似簡單，卻有幾個常見的坑：不確定該改哪個使用者 ID、兩次輸入不一致或密碼不符合 BMC 複雜度規則時只會看到一串不明所以的 `Unknown (0x22)`、改完也沒有任何機制驗證新密碼真的生效。這類操作一旦做錯又沒有退路——密碼設錯只能靠第二個 BMC 管理員帳號或重設 BMC 救回。README 開頭就用整段警語把這件事挑明：「這個動作無法復原」。這正是 PVT／量產線要把一批機器的 BMC 密碼統一改成同一組值、或是 BMC 網頁連不上時的救援場景，最需要工具把流程鎖死的地方。

## 技術重點

實際下載並讀過 README 與 394 行的 `BMC_Password_Change.sh` 後，幾個值得注意的設計：

- **先印身分卡，再動手改密碼**：執行流程的第三步固定會先列出主機名、型號、序號、BMC 廠牌／韌體／IPMI 版本、BMC IP 與目前使用的 LAN 通道，強迫使用者在改密碼前先確認「現在到底在哪一台機器上」，避免在錯的機器上動手。
- **LAN 通道自動偵測＋可覆寫**：依序嘗試常見的 1、2、3、8 通道找出可用的 BMC LAN channel，也保留 `--channel N` 手動指定的退路，對應不同廠牌 BMC 通道編號不一致的現實狀況。
- **密碼刻意不落地**：互動模式下密碼完全由 `ipmitool` 自己提示輸入兩次，不經過這支腳本、不出現在指令列、環境變數或日誌裡；非互動模式（`--password-env` + `--user-id` + `-y`）雖然支援批次操作，但 README 明確警告密碼會短暫出現在 `ps` 可見的指令列，只建議在可信任的單人機器上使用。日誌檔固定用 600 權限寫到 `logs/`，且只記錄動作與使用者 ID/名稱，不含密碼本身。
- **改完立刻用本機介面驗證**：`ipmitool user test` 在修改後立刻驗證新密碼是否真的生效，而不是假設 `ipmitool` 回傳成功就代表密碼真的可用；`-y` 這個跳過確認的參數被設計成必須搭配 `--user-id` 才能用，杜絕「沒指定對象就自動改密碼」的誤用路徑。
- **對驗證狀態誠實交代**：README 明確寫「已用模擬的 `ipmitool` 驗證過 `--list`、互動修改＋驗證、兩次輸入不一致、密碼太短被拒、確認時取消、非互動＋`-y`、`--dry-run`、參數錯誤、非 root、驗證失敗、日誌不含密碼等情境，但尚未在真實 BMC 上跑過」，並建議第一次上機先用 `--list` 與 `--dry-run` 確認通道與使用者 ID 無誤，再做實際修改——跟同系列其他 BMC 工具一樣，把「測過什麼、沒測過什麼」的邊界說清楚。

## 可延伸應用角度

- 可以跟先前介紹過的 BMC 風扇 SKU 切換工具、`get_bmc_bios_info` 之類的 BMC/IPMI 系列串成「BMC 維運安全腳本」合輯，重點放在同一套防呆骨架——身分卡、逐字確認、敏感資料不落地、修改後立即驗證——怎麼套用在不同的「一旦做錯就很難復原」的 BMC 操作上。
- 「密碼完全不經過腳本、只讓底層工具自己提示輸入」這個設計本身值得獨立做一支短片，講解寫會碰到密碼或密鑰的自動化工具時，該怎麼在互動模式與非互動（批次）模式之間取捨安全性與可自動化程度。
