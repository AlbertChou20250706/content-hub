> 來源路徑：`README_ToolDB-紀錄CIP/`（`README_ToolDB-紀錄CIP.xlsm` + 說明文件 `README_ToolDB-紀錄CIP.md`）

一份用純 Excel（`.xlsm`，含巨集）打造的「工具資料庫＋改進紀錄」雙表系統：`ToolDB` 工作表存放所有工具的主資料（ID、名稱、版本、狀態、路徑），`紀錄CIP` 工作表逐筆記錄每次對工具做了什麼、為什麼做、結果如何、花多少工時——兩張表用 `Tool ID` 欄位串起來，選一個 ID 就自動帶出對應的工具名稱，不必重複輸入。

## 為什麼值得關注

工程團隊手上工具一多，最常見的失憶症狀是：這支腳本上次改是什麼時候、改了什麼、為什麼要改，全部只存在維護者腦中或散落在不同的 commit message、群組對話裡。這份範本不是要導入一套新系統或資料庫，而是用大家都會用的 Excel，把「工具主檔」跟「異動流水帳」拆成兩張表、用公式連動起來，讓一個人（或一個小團隊）用最低的工具門檻，把「Why / What / Result / 工時」這種本來會流失的脈絡固定下來。它解決的不是技術問題，是記錄習慣的問題。

## 技術重點

實際拆開 `.xlsm`（OOXML 壓縮包）檢查，工作表只有兩張：`ToolDB`（sheetId 6）與 `紀錄CIP`（sheetId 8），跟說明文件描述的架構完全一致。連動靠三個具名範圍（Name Manager，`Ctrl+F3` 可見）：

- `ToolDB_New` = `ToolDB!$A$2:$I$4999`（工具主資料範圍，刻意留到 4999 列給未來擴充）
- `ToolIDList` = `INDEX(ToolDB[],0,1)`（沿用 Excel Table 結構化參照取 ID 欄）
- `ToolNameList` = `INDEX(ToolDB_New,0,2)`（改成引用 `ToolDB_New` 而非 Table，取 ToolName 欄）

`紀錄CIP` 的 `ToolName` 欄用 `=IFERROR(INDEX(ToolNameList, MATCH([@[Tool ID]], ToolIDList, 0)), "")` 自動帶出，`LogID` 用 `="L"&TEXT(ROW()-1,"0000")` 自動編流水號，`Date` 可選擇用 `=TODAY()`（會跳動）或 `Ctrl+;` 手動蓋一次性日期戳記。

值得注意的是實際檔案裡还留著一個沒清乾淨的舊具名範圍 `_xleta.IFERROR`，值是壞掉的 `#NAME?`——這剛好對應說明文件「Q3：名稱管理員反灰不能改」那段自述的踩坑經驗：作者原本想直接修改被鎖定的舊具名範圍失敗，索性放棄清理、改成新建 `ToolDB_New` 系列範圍繞過去，讓舊的壞掉範圍原封不動留在檔案裡。這是一個「與其修復技術債，不如在旁邊蓋一條新路」的真實決策痕跡，而非規劃出來的設計。

其餘部分屬正統 Excel 表單設計：Action / Tag / Status / 影響範圍全部用資料驗證下拉選單管理，避免「完成」「已完成」「Done」這種同義詞打散造成後續統計失真；README 裡也明確列出建議的欄位命名規範（Tool ID 固定 `T`+4碼、工時統一單位）與資料品質規範，等於把「怎麼填」也一併規格化，不只是給了表格結構。

## 可延伸應用角度

這份素材適合做成「用 Excel 公式做輕量工具治理」系列的其中一集，重點放在 `INDEX/MATCH` 搭配具名範圍做跨表連動、以及「具名範圍被鎖死怎麼辦」這個很多 Excel 老手都遇過但很少被寫下來的坑；也可以跟系列裡其他「工程團隊自建管理系統」的素材（例如已收錄的 RX4770M8 測試進度管理系統）放在一起比較，一個用 Excel 巨集、一個用網頁儀表板，呈現同一種「記錄治理」需求在不同技術門檻下的兩種解法。
