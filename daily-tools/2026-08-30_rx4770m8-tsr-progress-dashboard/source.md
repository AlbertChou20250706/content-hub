# RX4770M8-T50-2 測試進度看板 — 需求規格書跟實際程式碼之間，藏著一個沒被實作的公式

> 來源路徑：`工程團隊級測試進度管理系統模組等級-20251208T020338Z-1-001/`（`RX4770M8-T50-2 Test Status.html`、`12101040.html`，均建置於 2025-12-09～12-10）
> 設計者：Albert Chou　最後更新：2025-12-10

---

## 這是什麼

一支單一 HTML 檔案（零後端、零建置流程，用瀏覽器直接開）的測試進度看板，用來追蹤 RX4770M8-T50-2 專案裡每位工程師的測試進度：依 Owner × 日期畫出 PASS / FAIL / BLOCK 進度格線、保留一份接近 Excel 原始格式的 Summary table、支援 CSV / Excel 匯出，所有資料只存在瀏覽器 `localStorage`，不上傳任何伺服器。

## 為什麼值得關注

這個資料夾特別的地方，不是這支看板本身，而是裡面完整保留了一份逐條編號、跨版本迭代的需求文件（`RX4770M8-T50-2_Test_Status.md`，27 條需求，從最早的排版要求一路加到「個人進度不能超過 100%」這種具體邏輯要求）。這等於是一份「工程師用自然語言把需求一條條餵給 AI 寫程式」的活體紀錄，可以直接對照「當初打字要求了什麼」跟「AI 實際寫出了什麼」之間的落差——而這份落差是真實存在的（見下），不是空泛地講「用 AI 寫網頁」，而是有具體案例可以拆解。

## 技術重點（實際看過原始碼）

- **需求文件第 22 條明確要求「個人 total（pass+fail+block）不能超過 100%」，還附上完整的比例壓縮公式**：先算三個狀態各自的原始百分比 `pctPassRaw/pctFailRaw/pctBlockRaw`，若三者加總 `sumRaw > 100`，就用 `scale = 100/sumRaw` 把三個值等比例壓縮，確保 `pctPass+pctFail+pctBlock <= 100`。但實際翻 `updateProgressGrid()`（`RX4770M8-T50-2 Test Status.html` 與隔天的 `12101040.html` 兩個版本都一樣）只對 PASS/FAIL/BLOCK 三個狀態「各自獨立」做 `Math.min(100, rawPct)` 封頂，總和真的超過 100% 時只在 `console.warn` 留一行訊息（`'Owner',owner,'total over 100% cap'`），需求文件裡指定的比例壓縮邏輯完全沒有被寫進去。changelog 裡 v0.3.0 甚至白紙黑字寫「限制 P/F/B 總和不超過 100%」是這個版本的目的之一——但程式碼沒有跟上這個目的。
- **`<head>` 引入了 Chart.js（`cdn.jsdelivr.net/npm/chart.js`），但整份檔案搜尋不到任何一次 `new Chart(` 呼叫**：這是一個被載入卻完全沒用到的死重依賴，多半是從別的範本複製 head 區塊時順手帶進來的殘留，會讓瀏覽器多下載一份完全用不到的 JS。
- **資料模型是三個純前端結構**：`engineers[]`（工程師名單）、`holidays{日期:名稱}`（自訂假日字典）、`detailRows[]`（`{owner,detail,sheet,line,date,pass,fail,block}`），全靠 `safeLoad`/`safeSave` 包一層 try/catch 讀寫 `localStorage`，沒有任何後端。`countWorkdays()` 從指定起始日往後展開 `projectWeeks` 週，扣掉週末（`getDay()===0||6`）與自訂假日後算出實際工作天數，當作每位工程師的每日目標分母（`denom = defaultTarget × workdays`）。
- **三語系 i18n（繁中／英／日）確實完整覆蓋**：`I18N` 物件三種語言都有對應鍵值，搭配 `data-i18n` 屬性即時切換，語言與淺色/深色主題選擇都存進 `localStorage`，重新整理頁面後會維持使用者上次的選擇——這條需求（原始文件第 8、14、15 條反覆提到「請加回來」「沒有及時更換」）看起來是最後真的補齊了。
- **匯出功能走兩條路**：CSV 是純字串手動拼接（`Blob` + `URL.createObjectURL`），Excel 匯出則改用 SheetJS（`cdn.sheetjs.com/xlsx-latest`）產生真正的 `.xlsx`——同樣是全 CDN 引入、零建置流程的做法，跟整支工具「單檔案打開就能用」的風格一致。
- **資料夾裡還附了好幾份實際的 state 快照**（`RX4770M8-T50-2_state_202512*.json`，內含 `version`/`generatedAt` 版本標記），是使用者手動從瀏覽器 `localStorage` 匯出的備份檔。翻其中一份可以看到同一位工程師（Ava）連續貼了 7 筆內容幾乎一樣的紀錄——像是真人在測試時重複按到送出鍵留下的痕跡，說明這是一份真的被日常操作過的工具，資料夾裡附的不是展示用假資料。

## 可延伸應用角度

- 把需求文件第 22 條的公式跟 `updateProgressGrid()` 實際程式碼並排展示，做成「跟 AI 寫程式：你要求的跟它真的做出來的，常常有落差」系列教材的核心案例——這裡有精確到可以逐行對照的證據，比空泛提醒「記得驗收」更有說服力。
- Chart.js 載入卻從未使用的現象，可以獨立抽出來做一支「AI／範本產生的網頁裡常見的死重依賴」短片，提醒觀眾清理沒在用的 CDN script 標籤。
- 三語系 + 深色淺色主題 + `localStorage` 持久化 + 零後端 CSV/Excel 匯出的整套組合，可以當作「不開後端也能做出能用的內部工具」最小可行方案範例，跟已收錄的 WMI 硬體健檢報告（同樣是零依賴單檔 + 一鍵開啟）放進同一個系列，比較不同規模的「單檔案工具」怎麼各自取捨。
