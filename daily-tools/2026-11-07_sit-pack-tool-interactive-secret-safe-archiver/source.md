SIT_Pack_Tool 是一支互動式 bash 腳本，把 SIT 測試跑完後散落在 SUT／Client 多個資料夾的結果（`Compare_Log_*`、`OS_Event_Log_*`、`SIT_Report_*`、各種 `.log`/`.out`、Client 端日誌）掃描、勾選、打包成單一壓縮檔，附 SHA256 與檔案清單，方便上傳或歸檔。README 明確寫出它跟同一批 SIT 自動化（`Cycles/.../Auto_Test_v7`、`SIT_Unified_Command_Center`）完全分開、互不讀寫設定，純粹扮演「測試跑完之後，把結果收攏打包」這一個角色。

## 為什麼值得關注

測試資料夾裡經常混著 BMC / root 的帳密（`ipmi.conf`、`client.conf` 之類的設定檔），把整個資料夾直接打包丟給外部單位或上傳歸檔，很容易連密碼一起外流。SIT_Pack_Tool 把這個風險當成打包流程的第一等公民來設計：挑選範圍跟敏感內容過濾是兩層獨立的防護，而不是打包完再補救。這跟之前介紹過的「分風險等級自動化」（Refish_DMTF）是同一個方向的另一種應用——不是去改動 BMC/SUT 狀態的風險，而是「資料外流」的風險，一樣靠流程設計把風險往前攔住。

## 技術重點

讀過 README 與 933 行的 `SIT_Pack_Tool.sh` 後，幾個具體設計：

- **兩層機密防護，且各自獨立生效**：第一層是打包時的 `tar --exclude`（`SECRET_EXCLUDES` 陣列：`ipmi.conf`、`client.conf`、`*.bak`、`id_rsa*`、`id_ed25519*`、`*.pem`、`*.key`、`.regression_stdin`），在複製進暫存區那一刻就擋掉，即使這些檔案在被選中的資料夾範圍內。第二層是打包後對暫存內容做 `grep -rIlE` 掃描 `CRED_PATTERN='IPMI_PASS=|_PASS=|PASSWORD=[^ ]'`，命中的話列出檔名、預設詢問是否仍要繼續（讀取 `y/N`，不是 `y/n`，預設不繼續）。README 裡也老實說明「這是提醒，不是保證」，建議交件前自己再開 `MANIFEST.txt` 看一遍。
- **打包前先檢查可用空間，抓到的是「2 倍」這個細節**：`do_pack()` 用 `df -Pk` 讀輸出資料夾的可用空間，要求至少是所選項目容量的 2 倍（`sel_kb * 2 + 10240`）才放行——因為流程是先 `tar` 到 `mktemp -d` 的暫存資料夾再壓縮，暫存與最終壓縮檔會同時佔用空間，只檢查「壓縮後」大小會低估。
- **互動選擇指令做成一套小型 DSL**：在主選單 `[2]` 底下，可以打數字/範圍（`3 5 7-9`）、前綴 `-` 取消（`-2`）、`a`/`n`/`i` 全選/全不選/反選、`c <類別>` 整類勾選（`c Compare_Log`）、`s <日期>` 選「此日期後修改過的項目」（含 `s today`），指令可以連續輸入疊加使用，而不是一次只能做一種篩選。
- **MANIFEST 是雙重的**：`MANIFEST.sha256`（`find ... | sort -z | xargs -0 sha256sum`，可用 `sha256sum -c` 逐檔驗證）與 `MANIFEST.txt`（檔案大小、修改時間、路徑，依時間排序）分開產生，驗證（選單 `[4]` 或 `-V`）時先比對 checksum，再印出 `MANIFEST.txt` 前 15 行當摘要，不符合會直接顯示 `MISMATCH`。
- **單檔 HTML 報告，不依賴外部資源**：`PACK_REPORT.html`（套件內容）跟每次操作的 `tool_logs/*.html`（操作日誌）用同一套版型——深色頂欄＋全文搜尋＋可點擊篩選的彩色方塊（已打包／有排除機密檔／空項目／需處理，四色含優先序判定）＋中/英文介面切換＋深淺色切換，全部用內嵌 JS（`html_js()`）純前端完成，離線打開就能用，不用額外起 server。
- **腳本本身遵循一套固定的「Albert Style」撰寫慣例**：內部註解用日文附讀音（例如程式裡 `# メタ情報 (めた じょうほう - meta jouhou - ...)`），對使用者顯示的訊息一律英文；版本區塊有 `[ADD]`/`[FIX]`/`[PORT]`/`[KEEP]` 分類的變更歷史；路徑以 `SCRIPT_DIR` 為錨點，整個資料夾可直接搬移到任何 SUT/Client 執行。README 誠實標註「已用模擬資料夾驗證過流程，但尚未在真實 SUT/Client 上實跑，`tar.xz`/`zip` 路徑也還沒測過」。

## 可延伸應用角度

- 跟 Refish_DMTF 那篇可以做成互補對照：一個講「執行會動 BMC/SUT 狀態的驗證腳本時怎麼分風險並承諾還原」，這篇可以講「測試結束後怎麼安全地把結果資料打包外流，不連密碼一起送出去」——同一個 SIT 自動化流程，前段跑測試、後段收尾兩個階段各自的風險設計。
- 「兩層獨立防護（排除清單 + 事後內容掃描）」這個模式本身可以抽出來做一段科普，討論任何要打包/上傳測試資料的場景該怎麼設計安全網，而不是打包完才人工檢查。
- 單檔 HTML 報告（內嵌 CSS/JS、離線可開、雙語切換）這個版型已經在這批 SIT 工具裡重複出現（PACK_REPORT、操作日誌），適合剪一段「同一套報告版型怎麼被重複套用在不同工具上」的系列內容，呼應正在做的 SIT 自動化系列。
