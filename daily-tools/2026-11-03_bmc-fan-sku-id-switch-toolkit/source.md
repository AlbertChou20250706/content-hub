BMC_Fan_SKU_Tool 是一支用來改寫伺服器 BMC 內「風扇 SKU ID」的互動式 Bash 工具，把 SIT3 群組原本要手動跑四個步驟（確認 BMC → 讀目前值 → 寫入 → 回讀確認）再加上「cold reset → 重啟後再讀一次」的流程，整合成一支可互動、可帶參數、會自動產出報告的腳本。

## 為什麼值得關注

風扇 SKU ID 決定 BMC 要套用哪一張機型對應的 fan table（風扇轉速曲線），寫錯 SKU 不會讓系統當掉，但會讓風扇依照錯誤機型的曲線運轉——這種「看起來正常、實際上溫控已經偏掉」的隱性風險，正是最適合用工具把流程鎖死、強制每一步都回讀驗證的場景。更重要的是 README 裡引用了 BMC Release Note 的提醒：「先切換成正確的 SKU ID，再刷 BMC 韌體」，代表這支工具不只是單純的數值修改器，而是韌體刷新流程裡一個順序敏感、容易被跳過的前置步驟。

## 技術重點

實際下載並讀過 README、`BMC_Fan_SKU_Tool.sh`（749 行）與 `sku_table.conf` 後，幾個值得注意的設計：

- **OEM raw 指令被完整封裝成讀/寫一組**：讀取是 `raw 0x2e 0x0e 0xfd 0x19 0x00 0x01`，寫入是 `raw 0x2e 0x0d fd 19 00 01 XX`，成功回應固定以 `fd 19 00` 開頭，腳本只負責把這組 OEM 指令串起來、解析回應、留下紀錄，刻意不去動指令本身——降低了工具本身引入新錯誤的風險面。
- **六步驟的驗證鏈，任何一步失敗就停**：確認 BMC 活著（`mc info` 重試 6 次 × 10 秒）→ 讀目前值 → 顯示「目前→目標」要求確認後寫入 → 立即回讀確認等於目標 → cold reset（等待 60 秒、最長輪詢 240 秒等 BMC 回來）→ **重啟後再讀一次**，確認設定真的被保留而不是只存在記憶體裡。最後這一步是整支工具最關鍵的設計——很多類似工具寫完就回報成功，但這支工具堅持要在 reboot 之後再驗一次。
- **SKU 對照表外部化成 `.conf`**：新機型只要在 `sku_table.conf` 加一行 `0xNN|機型|備註`，不必改腳本；同時支援用 `--model <關鍵字>` 做部分比對選 SKU，但要求必須剛好命中 1 筆，避免模糊比對寫錯 SKU。
- **in-band／out-of-band 雙模式**：本機用 `ipmitool` 直連，或用 `-H -U` 搭配環境變數 `IPMI_PASSWORD` 做 out-of-band（lanplus）遠端操作 BMC，密碼不給就會轉成隱藏輸入而不是明文參數。
- **誠實標注驗證狀態**：README 明確寫「已用模擬的 `ipmitool` 驗證完整流程、跳過寫入、機型比對、拒絕寫入、非法 SKU、dry-run 等情境，但尚未在真實 BMC 上實跑」，並指引使用者第一次上機要先 `--read` 確認回應格式、再 `--dry-run` 看指令，最後才真的寫入——這跟 FRU 系列工具一樣，把「測過什麼、沒測過什麼」交代得很清楚。

## 可延伸應用角度

- 可以跟先前介紹過的 FRU MAC/UUID 寫入工具、OTP 安全開機熔斷寫入工具串成「RX4770M8 韌體層級識別與校正操作」系列，呈現同一台伺服器在量產前校正階段，哪些 BMC OEM 設定需要被工具化、哪些必須搭配 reboot 驗證。
- 「寫入前確認、寫入後立即回讀、reboot 後再驗一次」這套三段式驗證模式，本身就值得獨立做一支短片，講解寫 BMC/BIOS 層級自動化工具時，為什麼「寫完」跟「寫對且保留下來」是兩件不能省略其中一件的事。
