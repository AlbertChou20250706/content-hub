「Cycles」是 Albert 自製的伺服器電源循環回歸測試框架，用「設定器（`ver.sh`）→ 控制器（`regression_test.sh`）→ 引擎（`Albert_Ultimate_Cycle_Test.sh`）」三層架構，自動跑 REBOOT／AC／DC 三種斷電情境的重複壓力測試，並在每一圈之間比對硬體基準線，確認系統重開機後「長得還是原來那樣」。

## 為什麼值得關注

這套框架同時維護了 RHEL 8/9/Rocky、SUSE、Ubuntu、Windows、RHEL 10 五條 OS 分支，而且版本號彼此並不同步——RHEL8/9 的引擎停在 5.9，SUSE 最新是 5.13，Ubuntu 版已經到 5.14，RHEL10 版則直接跳到 6.0（因為多了 TR-14 真實 AC 切電功能）。這種「同一套邏輯、多條分支各自往前跑」的真實狀態，加上每個 OS 資料夾底下都看得到 `Claude/`、`Gemin(i)/`、`Auto_Test/` 這類並存的開發快照——代表 Albert 很可能是借助不同 AI 編碼助手，分頭在各 OS 分支上維護、修正、甚至互相比對結果。這跟團隊已經發布過的《Suno 提示詞：Cycle v6.0》《Suno提示詞_Cycles與Cleanboot》兩首歌背後，是同一套工程系統——歌詞唱的「Reboot, AC, DC」「TR-14」「Compare-Object」,全部都能在這裡的原始碼和 README 裡找到逐條對應的技術決策。

## 技術重點

實際下載並讀過整個資料夾（五條 OS 分支、約 20MB 腳本與文件）之後，幾個值得注意的地方：

- **三層架構與可攜性演進**：`ver.sh` 負責互動式設定測項與圈數（AC/DC 需要 BMC 資訊時，會把帳密寫進權限 600 的 `config/ipmi.conf`，用 `read -s` 隱藏輸入）；`regression_test.sh` 是依佇列逐一執行測試類型的控制器；`Albert_Ultimate_Cycle_Test.sh` 是真正執行斷電/重開機的引擎。RHEL10 v6.0 版把 `tr-14` 工具路徑從寫死的 `/usr/bin/tr-14` 改成相對路徑 `./tools/tr-14`，是一個很具體的「從個人機器專用腳本變成可攜式部署包」的重構案例。
- **v6.0 的核心賣點是「不再假裝斷電」**：舊版 AC 測試其實是用 `IPMI poweroff` 模擬斷電（本質上跟 DC 測試一樣），v6.0 改用 TR-14 硬體繼電器透過 RS-232／USB-Serial 真的切斷 AC 電源（`TR14_OFF_SECONDS=50` 控制斷電秒數），並且在偵測不到 TR-14 工具或權限不足時，會明確印出警告「降級使用 IPMI poweroff（非真實 AC）」而不是悄悄蒙混過去。
- **環境 Preflight 檢查是從真實踩坑長出來的功能**：v6.0 新增 `check_environment.sh`，會逐項檢查核心工具、systemd、`ipmitool`／`dmidecode`／`rtcwake`、TR-14 二進位與 serial port 是否就緒，缺什麼直接印出對應的 `dnf install` 指令——這類「工具會告訴你怎麼修，而不是只回報失敗」的設計，加上 REBOOT→AC→DC 之間自動等 5 分鐘讓 log 收尾，都是從實際測試現場的痛點反推出來的。
- **最有意思的是一份「自我打臉」的 README**：`stop_dc_cycles_now/README.md` 是 Albert 寫給自己的一個「一鍵停止腳本」的誠實檢討——他對照 Cycles 框架原始碼後發現，這支快速寫的停止腳本其實沒有真的整合進 v5.x 架構：它建立的停止旗標檔沒有任何框架腳本會讀取；腳本用 `set -e` 搭配 `touch` 建立狀態檔，若目錄不存在會直接中止、後面步驟全部不執行；不會停用開機自動續跑的 systemd 服務，殺掉行程後重開機可能又自動跑起來；而且用很寬鬆的 `pkill -9 -f cycle` 比對，可能誤殺不相關行程。最後建議工程師改用框架內建的 `regression_test.sh --abort`（會正確取消 RTC 鬧鐘、移除續跑服務、清狀態檔）。這種「做了一個解法、自己對照原始碼驗證後發現不可靠、寫下來提醒自己和別人」的紀錄方式，比大多數「教你怎麼做」的教學文件更有參考價值。
- **引擎對中斷訊號有正確處理**：`Albert_Ultimate_Cycle_Test.sh` 對 `INT`／`TERM` 訊號有 trap，會取消 RTC 鬧鐘並儲存狀態後以 130 結束碼退出，因此一般情況下 `Ctrl+C` 或 `kill -TERM` 比 `kill -9` 安全——但光中斷行程仍擋不住開機自動續跑，呼應上一點的檢討。

## 可延伸應用角度

- 可以直接跟已發布的《Suno 提示詞：Cycle v6.0》串成一支「從原始碼到歌詞」的對照影片：把 README 裡 TR-14、`TR14_OFF_SECONDS=50`、環境檢查流程，一一對應到歌詞段落，示範技術文件怎麼被轉譯成敘事。
- 「自我檢討型 README」本身就值得做成一支獨立短片——用 `stop_dc_cycles_now` 這個案例，講工程師在寫完一個「看起來能用」的腳本後，回頭用原始碼交叉驗證、誠實記錄限制的習慣，是比寫文件更重要的工程素養。
- 五條 OS 分支版本不同步（5.9／5.13／5.14／6.0）也是很好的「多環境維護債」案例，適合搭配別的版本管理／維運債主題內容一起討論。
