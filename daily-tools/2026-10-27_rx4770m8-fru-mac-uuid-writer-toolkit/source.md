FRU_Automatic 是一套跨 Windows／Linux 的伺服器 FRU（Field Replaceable Unit）資料讀寫工具集，讓工程師透過選單或命令列參數，直接改寫伺服器主機板、機殼的 FRU EEPROM 內容（序號、型號、BMC MAC 位址、系統 UUID 等識別資訊），取代過去純手動拼 `ipmitool`／`IPMIView` 指令、容易因位元組錯位而寫壞識別資訊的流程。

## 為什麼值得關注

RMA 重工、產線機殼互換、主機板更換後，常常需要重新寫入 FRU 識別資訊，手動操作風險高、沒有回讀驗證就等於「寫完賭它是對的」。這個資料夾裡同時存在三套獨立實作——Windows 選單批次檔 `Fru.bat`、較新的 PowerShell 工具 `FRU_Tool_v1.2.1.ps1`（附自動回讀驗證與 HTML 報告），以及 Linux 互動選單 `fru.sh`——反映出這是一支持續被使用、被迭代的真實工具，而不是寫一次就沒人再碰的腳本。

更值得注意的是：兩份 README 都誠實記錄了 2026-09-24 同一天抓出並修好的**阻斷性語法錯誤**——Linux 版 `fru.sh` 裡 `defined_color()` 函式被整段註解掉，但結尾的 `}` 沒有一起註解，`bash -n` 直接判定語法錯誤，腳本從未真正進過選單；Windows PowerShell 版 `FRU_Tool_v1.2.1.ps1` 則是一個 here-string 的結尾寫錯（該用 `"@` 卻只寫了單獨的 `"`），把 MAIN 主流程與驗證函式整段吞成字串常數，導致 `Check_Code.bat` 什麼檢查都沒做卻一路顯示 `PASS`。兩個 bug 存在的時間都不短，而且都是「表面上看起來在運作，實際上完全沒執行到核心邏輯」的隱蔽類型，修復後也老實標注「語法通過、`-CheckOnly` 驗證通過，但真正的 FRU 讀寫尚未在實機測試」——這種把「驗證到什麼程度、還沒驗證什麼」分得清清楚楚的紀錄習慣，比大多數內部工具的 README 更透明。

## 技術重點

實際下載並讀過三份 README 與腳本後，幾個值得注意的設計：

- **寫入流程是標準的 bin↔ini 轉換管線**：`IPMIVIEW64.exe` 負責讀出 FRU 二進位檔，`IPMI_FRU64.exe` 轉成可編輯的 `.ini`，工程師用記事本／`gedit` 編輯後轉回 256 bytes 的 bin 再寫入，三個平台版本都遵循同一套「讀 → 轉 → 編輯 → 轉 → 寫 → 回讀驗證」流程。
- **回讀驗證規則用 CSV 描述**：PowerShell 版的 `verify.csv` 以 `Key,Expect,Mode` 三欄描述每個欄位該長什麼樣，`Mode` 支援完全比對（`=`）與正規表示式比對（`~=`），找不到 Key 直接判定 FAIL，這把「寫完到底對不對」從人工目視檢查變成可重複執行的規則比對。
- **結束碼設計覆蓋到具體失敗階段**：`2`（缺必要執行檔）、`21`（INI 格式錯誤）、`30/31`（讀取相關失敗）、`32～35`（bin→ini／編輯／ini→bin／寫入各階段失敗）、`40`（驗證失敗且要求中止），讓這支工具可以被其他自動化流程串接，而不只是互動式工具。
- **UUID 寫入的邏輯很具體**：抓第一張 Intel I210 網卡的 MAC 位址，做 SHA-1 後取前 32 個十六進位字元當作系統 UUID，透過 `Pc_Ident64` 寫入，再用 `dmidecode -s system-uuid` 驗證結果——用網卡 MAC 的雜湊值當 UUID 來源，確保同一片主機板重跑也會得到一致的值。
- **一個值得留意的安全瑕疵**：`Fru.bat`、`mac.bat`、`SOP.txt` 以及 `FRU_Tool_v1.2.1.ps1` 內都寫死了預設的 BMC／iRMC 帳號密碼常數，README 也直接寫了警語「請勿把這個資料夾原樣分享或上傳到公開位置，建議改成執行時輸入」——這是內部工具常見但容易被忽略的風險，開發者自己也意識到了並記錄下來。

## 可延伸應用角度

- 適合做成「個人工具的誠實除錯日記」系列：同一天修好兩支完全獨立（PowerShell／Bash）的隱蔽型阻斷性 bug，而且清楚標注修復範圍跟尚未驗證的部分，這種工程紀律本身就是值得推廣的案例教學素材。
- 可以跟先前介紹過的 BMC/BIOS Redfish 比對工具、OTP 安全開機熔斷寫入工具串成「RX4770M8 硬體身分資訊系列」，呈現同一台伺服器在不同生命週期階段（研發驗證、量產前、RMA 維修）各自需要處理哪一層識別資訊。
- 硬編碼帳密這個發現也可以單獨拉出來做「內部自動化腳本的資安盲點」短片，用這幾支腳本當真實案例，講解為什麼就算是內網工具也不該把帳密寫死在程式碼裡。
