《Suno 提示詞：Cycle v6.0》是 Albert 把內部 RHEL 10 真實 AC 斷電循環測試腳本的 README，轉寫成可以丟進 Suno AI 生成完整歌曲的提示詞模板——包含 Style of Music、Exclude styles、逐段 Lyrics 與一組「唸錯詞修正」技巧，目的是把一份工程 SOP 變成團隊內部可傳唱、記得住的技術歌曲。

## 為什麼值得關注

SIT 測試團隊的 Cycle 腳本經過好幾個版本迭代，v6.0 的重點是把「假斷電」換成「真斷電」：之前版本用 IPMI 下指令模擬斷電，這次改用 TR-14 繼電器真的切斷 AC 電源，是測試可信度上的一個關鍵升級。但這種版本差異通常只會寫在 README 的變更記錄裡，沒人會特別記得。這份提示詞把「不再假裝、真實切電」這個最重要的賣點，直接寫成副歌 hook，用一首歌把腳本的技術決策烙進團隊記憶裡——這是一個很具體的「用 GenAI 把工程文件轉化成好記內容」的案例，跟資料夾裡另一份《GenAI and AI Agent在職場上的應用》談的方向互相呼應。

## 技術重點

實際讀過這份提示詞檔案後，幾個值得注意的設計：

- **取材對應表**：檔案開頭就列出一張「腳本重點 → 歌裡怎麼用」的對照表，把 README 的技術細節拆成歌曲段落——環境檢查 5 步對應 Verse 1；TR-14 真實切電這個核心賣點對應副歌 hook；`TR14_OFF_SECONDS=50` 這個設定值被直接寫進歌詞變成「五十秒的黑暗」；REBOOT→AC→DC 之間的 5 分鐘等待對應 Verse 2；最後打包 result 對應 Final Chorus／Outro。這是一種把「參數值」逐句轉譯成「敘事」的做法，而不是空泛地唱「測試很重要」。
- **技術細節真的被唱出來**：歌詞裡出現 `ipmitool`、`dmidecode`、`tr-14`、`rtcwake`、`BMC always-on`、`RS-232` 這些具體名詞與相對路徑描述（"tr-14 躺在 tools 裡，相對路徑不迷路"），顯示這不是隨便生成的套版歌詞，而是真的對照腳本邏輯逐句寫出來的。
- **Suno 咬字修正技巧**：檔案附了一段「小技巧」，記錄 Suno 容易唸錯哪些工程術語（`tr-14`、`ipmitool`、`rtcwake`、`always-on`），並給出替代拼法（`T R 十四`、`I P M I tool`、`R T C wake`、`always on`）——這是實際測試過 Suno 生成結果後踩坑、回頭修正提示詞的紀錄，而不是理論上的建議。
- **版本家族**：這份 v6.0 取代的是先前的 Windows 版《Cycle》提示詞，同資料夾另外還有《Suno提示詞_Cycles與Cleanboot.md》(Watchdog 主題，維持不變) 與更早的《技術歌曲創作_Cycles與Cleanboot.md》，可以看出這是一個持續在迭代、針對不同測試腳本（Cycle、Watchdog、Cleanboot）分別維護提示詞的小型「提示詞工程」實踐。
