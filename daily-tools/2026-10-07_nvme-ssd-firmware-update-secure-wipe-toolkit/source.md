NVMe_SSD_Firmware_Update_Tool 是兩支搭配使用的 Linux Bash 腳本，專門處理 NVMe SSD 在 SIT 驗證機台上最容易出意外的兩件事：韌體更新（`NVMe_Firmware_Update_.sh` v1.9.1）與多碟安全清除（`nvme_wipe.sh` v1.0.0）。

## 為什麼值得關注

NVMe 韌體更新和資料清除都是「一步錯、全盤垂」的高風險操作：韌體寫錯型號可能讓 SSD 直接變磚，清除資料如果不小心連開機碟一起清掉，整台機台就報銷。這兩支腳本的設計重點都放在「怎麼讓操作者不要手滑」——一支是把風險老實寫在 README 最前面讓人自己當心，另一支則直接用程式邏輯把地雷排除在互動流程之外，兩種設計哲學的對比本身就很有教學價值。

## 技術重點

實際下載並讀過兩支腳本與 README 後，重點如下：

- **韌體更新腳本刻意不做保護**：`NVMe_Firmware_Update_.sh` 會掃描所有 `/dev/nvme[0-9]*` 控制器（v1.9.1 修掉了 glob 只認單位數的 bug，改成支援 `nvme10`、`nvme11` 以上），讓使用者選「單一控制器」或「全部更新」，但選定後立刻對目標執行 `nvme fw-download` + `nvme fw-commit -a 1`，**沒有機型比對、沒有二次確認**。`.bin` 韌體檔也是直接抓「目前目錄下依檔名排序的第一個 `*.bin`」，資料夾放錯檔案就會選錯。README 把這些坑全部用警告區塊列在最前面，等於用文件補程式邏輯沒做的防呆。
- **清除腳本反過來把防呆寫進程式邏輯**：`nvme_wipe.sh` 開機先用 `findmnt`（含 `/`、`/boot`、`/boot/efi`、btrfs 子卷）加 `swapon` 反查所有掛載點背後的實體 NVMe 磁碟，自動列入 `PROTECTED` 清單；真正執行清除前的 `execute_wipe` 還會再呼叫一次 `_safety_recheck` 二次覆核。候選清單特別標出 Serial Number，因為 `nvmeX` 的裝置編號重開機後可能漂移，序號才是可靠識別依據。
- **清除方式做成對照表而非單一硬編碼**：五種方式（Secure Erase / Crypto Erase / Sanitize Block Erase / Sanitize Crypto Erase / TRIM Only）對應 `nvme format --ses=1/2`、`nvme sanitize --sanact=2/4`、`blkdiscard --force`，速度與徹底程度不同，腳本對 Sanitize 類還會輪詢 `nvme sanitize-log` 的 `SSTAT`/`SPROG` 直到背景清除真正完成才繼續，避免誤判「指令送出成功」＝「清除已完成」。
- **雙重確認機制**：需輸入關鍵字 `ERASE` 才會進入可自訂秒數的倒數，倒數中仍可 `Ctrl+C` 中止；另外提供 `--dry-run` 只列清除計畫不執行任何寫入，適合正式操作前先跑一次對照候選清單與保護清單是否正確。
- **輸出三份同步**：CLI 彩色輸出、純文字 log（方便 `grep`／歸檔）、深色主題 HTML 報表三邊同時產生且時間戳記統一，韌體更新腳本的 HTML 報表則是簡化版的 PASS/FAIL 色塊表格——兩支腳本在「人要看」與「機器要處理」的輸出分離上做法一致。
- 有個小細節：腳本內部註解用日文（含假名讀音）寫，但所有使用者會看到的輸出（CLI、log、HTML）一律英文，刻意避開跨環境 locale 顯示亂碼的問題。

## 可延伸應用角度

- 適合做成「危險操作的兩種防呆設計哲學」對比教學：同一類風險（寫壞硬體／清錯硬碟），一支選擇「文件示警 + 使用者自律」，另一支選擇「程式邏輯硬擋」，可以討論什麼情境該用哪種取捨。
- 技術重點裡的 OS 碟自動保護邏輯（`findmnt` + `swapon` 反查實體磁碟）本身就是一個獨立的「如何在腳本裡安全識別系統碟」小教學，可以單獨抽出來當片段示範。
- 可以搭配既有的儲存壓力測試系列（`sit-storage-stress-toolkit`）做成「NVMe SSD 全生命週期維運」系列：壓測 → 韌體更新 → 清除重置，串成一條完整的驗證機台 SOP 敘事線。
